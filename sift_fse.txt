# 3. Engineering Principles

The Sift codebase MUST follow these principles.

## 3.1 Evidence over assertion

The system must distinguish:

* observed fact
* sourced evidence
* derived analysis
* assumption
* unknown
* counter-evidence
* validation result

The application must never represent an unsupported inference as an observed fact.

## 3.2 Provenance by default

Material research claims must be traceable to their source.

## 3.3 Structured AI

LLMs must produce schema-validated structured outputs.

Free-form model output must never directly mutate trusted application state.

## 3.4 Asynchronous by design

Research is a long-running workflow.

The web request must not remain open while the entire research pipeline executes.

## 3.5 Failure is a first-class state

Every external dependency can fail.

The system must explicitly handle:

* timeout
* rate limit
* malformed response
* unavailable source
* model failure
* search failure
* worker failure
* database failure
* payment failure
* authentication failure

## 3.6 No fake completion

A partially completed research run must never be represented as complete.

## 3.7 Idempotency

Retrying a job must not accidentally create duplicate analyses, duplicate billing events, duplicate evidence records, or duplicate experiments.

## 3.8 Provider abstraction

Search and LLM providers must be replaceable without rewriting the application domain.

# 41. Source Retrieval

The retrieval subsystem must:

1. Resolve URL.
2. Fetch content.
3. Record retrieval timestamp.
4. Record HTTP status.
5. Extract usable content.
6. Detect publisher/title/date where possible.
7. Calculate content hash.
8. Store normalized metadata.
9. Preserve canonical URL.
10. Record accessibility failures.

If a source cannot be accessed:

```text
ACCESS_UNAVAILABLE
```

Do not infer its content.

---

# 42. Source Deduplication

The system must detect:

* identical URLs
* canonical URL equivalents
* identical content hashes
* syndicated copies
* duplicated claims from the same underlying source

Ten articles repeating one press release must not be represented as ten independent pieces of evidence.

---

# 43. Evidence Independence

Evidence records must include an independence relationship where relevant.

Example:

```text
Source A → original government dataset

Source B → article quoting Source A

Source C → blog quoting Source B
```

These should not be counted as three independent sources.

* population/customer segment
* time period

# 52. Report Quality Gate

An analysis may become `COMPLETE` only if:

* required research modules finished
* minimum source requirements satisfied
* critical assumptions investigated
* counter-evidence search completed
* source metadata validated
* citation coverage passes
* numerical consistency passes
* geography/population checks pass
* synthesis schema passes
* no unresolved critical pipeline failures remain

Otherwise:

```text
PARTIAL
```

or:

```text
RESEARCH INCOMPLETE — INSUFFICIENT EVIDENCE
```

# 94. Implementation Completeness Protocol

This section is mandatory.

The AI coding agent must treat the repository as an implementation project, not as an opportunity to redesign Sift.

## Rule 1 — No silent invention

Do not invent:

* product functionality
* workflows
* business rules
* pricing
* permissions
* AI objectives
* research methodology
* evidence standards

If genuinely unspecified, flag it.

## Rule 2 — No silent omission

Do not skip a requirement because it is difficult.

Record:

```text
Requirement
Status
Reason
Affected components
Required decision
```

## Rule 3 — No fake implementation

A UI mockup is not implementation.

A button that does nothing is not implementation.

Hard-coded research results are not implementation.

A simulated payment is not billing.

Placeholder citations are not evidence.

## Rule 4 — No unverified completion

A feature is complete only when:

```text
Frontend
+
Backend
+
Database
+
AI/Worker where applicable
+
Validation
+
Error handling
+
Tests
+
Acceptance criteria
```

are satisfied.

## Rule 5 — Preserve provenance

Never detach an evidence claim from its source.

## Rule 6 — Preserve uncertainty

Do not transform:

```text
Unknown
```

into:

```text
Probably true
```

without evidence.

## Rule 7 — Preserve partial state

Never convert:

```text
PARTIAL
```

into:

```text
COMPLETE
```

just to make the interface look finished.

## Rule 8 — External dependencies are real dependencies

If a provider is unavailable, implement the correct failure state.

Do not substitute fake production data.

## Rule 9 — Ask/flag rather than invent

When a decision cannot be resolved from the Product PRD, Engineering TPRD, established architecture, or existing implementation conventions:

```text
FLAG DECISION
```

rather than silently choosing product behavior.

